# Offline CDK infrastructure

Applies to this tree; inherit parent guides. `package.json` requires exact Node
24.15.0. These definitions and synth artifacts are not a deployed environment.

## Commands

From the repository root:

```sh
npm --prefix HostedService/infra ci
npm --prefix HostedService/infra run typecheck
npm --prefix HostedService/infra run generate:migration-manifest
npm --prefix HostedService/infra run verify
```

`verify` (also `test`) uses `scripts/run-offline-verify.mjs` to strip ambient
`AWS_*`, `CDK_*`, `ROOMSCAN_*` values, inject checked-in synthetic configuration,
build the service, type-check, run local assertions/mutations, synthesize and
inspect. Prefer it over direct `synth`, which needs complete explicit inputs.
Install the service and web dependencies first; infrastructure builds consume both.

## Boundaries

- `src/stacks/`: assembly and least-privilege resources; `src/functions/`:
  deployment entrypoints; `src/aws/`: concrete AWS clients/providers;
  `src/migration-operator/`: reviewed digest-bound migration execution;
  `src/policy/`: emitted-template policy checks.
- Keep each runtime lane's credential/capability distinct. Do not widen S3
  prefixes, KMS conditions, DB roles or queue messages to make composition easier.
- Preserve private/versioned encrypted objects, targetless validation queues,
  complete migration/VPC/IAM roots, no public asset bucket/CDN and explicit
  audit/alarm/owner configuration.
- Keep test identifiers and `.invalid` values synthetic. Live AWS calls,
  bootstrap/deploy/diff, secret creation/rotation and production operator inputs
  require separate authorization; do not infer permission from offline synthesis.

## Generated files and evidence

- `assets/migration-manifest.json` is regenerated by the command above from
  `../db/migrations/` and `../db/migrate.mjs`; review any resulting digest change.
- `dist/`, `.test-dist/`, `cdk.out/`, `cdk.context.json` and `evidence/*.json`
  or `*.log` are reproducible outputs. Edit source/scripts, not emitted assets.
- Tests are `test/*.test.ts`; mutations are `test/mutations.ts`. Keep real
  template/bundle inspection and detected/restored mutation coverage together.
- Treat counts in the older local README as historical; use actual current
  output, not a hardcoded expected success count.
